## 1. Business Context

**NASF** is an Android **Decision Support System (DSS)** for **nutrient management and yield estimation** in the **rice–wheat cropping system** of the **Indo-Gangetic Plain (IGP)** — covering states such as **UP, Bihar, Punjab, and Haryana**.

The splash screen copy (English + Hindi) states this explicitly:

- *"DSS for Nutrient Management in Rice-Wheat System in IGP"*
- *"आईजीपी में चावल-गेहूं प्रणाली में पोषक तत्व प्रबंधन के लिए डीएसएस"*

### Target Users

The app is aimed at **farmers and extension workers** who need help with:

| Area | What the App Does |
|------|-------------------|
| **Authentication** | Register / log in against a PHP API (`login.php`, `signup.php`) |
| **Yield estimation** | Predict grain yield from location, soil, and farm-management inputs |
| **Crop advisory** | "Crop Management Advisory" from location + crop + target yield (soil inferred server-side) |

### Domain Scope

- **Crops:** Rice (चावल) and Wheat (गेहूँ)
- **Variety duration:** Short / Medium / Long duration
- **States (IGP):** UP, Bihar, Punjab, Haryana
- **Language:** Bilingual UI (Hindi + English)
- **Institutional context:** ICAR / IARI branding — agricultural research / extension product

### Technical Infrastructure

Backend services run on an **internal network**:

| Server | Purpose |
|--------|---------|
| `http://172.17.30.66/loginapi/` | User authentication (PHP) |
| `http://172.17.30.99:5000/` | ML / prediction / advisory APIs |

## 2. Login.kt Analysis

**File:** `app/src/main/java/com/example/nasf/Login.kt`  
**Layout:** `activity_login.xml`

`Login` is the authentication gate after the splash screen. It wires four UI elements and two navigation paths.

### UI Components

| View ID | Type | Purpose |
|---------|------|---------|
| `login_username` | EditText | Username input |
| `login_password` | EditText | Password input |
| `login_btn` | Button | Submit login |
| `signupText` | TextView | Navigate to Signup |
| `progressBar` | ProgressBar | Shown during API call |

### User Flow

| Step | Behavior |
|------|----------|
| 1 | User enters **username** and **password** |
| 2 | **Sign up** link → opens `Signup` activity (`finish()` on Login) |
| 3 | **Login** tap → **`MainActivity` opens immediately** (before API validation) |
| 4 | If both fields non-empty → POST to `login.php`; show Toast (`Login Success` or error); open **`MainActivity` again** and `finish()` |
| 5 | If fields empty → Toast *"All fields required"* (but `MainActivity` may already have opened in step 3) |

### API Integration

- **Endpoint:** `http://172.17.30.66/loginapi/login.php`
- **Method:** POST
- **Parameters:** `username`, `password`
- **Library:** `com.vishnusivadas.advanced_httpurlconnection.PutData`
- **Success response:** `"Login Success"`

### Known Behavior Issue

Login is **not enforced** in practice:

1. On **Login** button click, `MainActivity` is started **immediately** (lines 45–46), before credentials are validated.
2. If fields are filled, the API runs asynchronously; on completion, `MainActivity` is started **again** and Login is finished.
3. Empty fields show a Toast, but the user may already be on the dashboard from step 1.

**Implication:** The dashboard is reachable without successful server authentication. API success/failure only affects the Toast message on the first navigation path.

### Code Reference (Navigation Logic)

```kotlin
login.setOnClickListener {
    val intent = Intent(this, MainActivity::class.java)
    startActivity(intent)   // Navigates IMMEDIATELY, before API check

    val username = login_username.text.toString()
    val password = login_password.text.toString()

    if (username != "" && password != "") {
        progressBar.visibility = ProgressBar.VISIBLE
        handler.post(Runnable {
            val putData = PutData("http://172.17.30.66/loginapi/login.php", "POST", field, data)
            // ... API call and Toast ...
            val intent = Intent(applicationContext, MainActivity::class.java)
            startActivity(intent)   // Navigates AGAIN after API
            finish()
        })
    } else {
        Toast.makeText(applicationContext, "All fields required", Toast.LENGTH_SHORT).show()
    }
}
```

### 4.5 ManualDetails

| Property | Value |
|----------|-------|
| **File** | `ManualDetails.kt` |
| **Layout** | `activity_manual_details.xml` |
| **Purpose** | Yield prediction with full soil laboratory data |

**Input sections:**

1. **Location:** State (UP, Bihar, Punjab, Haryana), Longitude, Latitude
2. **Soil chemistry:** pH, EC, OC, Available N/P/K, S, Zn, Fe, Mn, Cu
3. **Management:** Crop, variety, residue, N/DAP/MOP, zinc sulphate, FYM, sowing/harvest dates (Julian DOY), irrigation count, grain yield target

**Processing:**

- Fertilizer conversions (N, P, K adjustment formulas)
- Date picker converts calendar dates to Julian day-of-year
- POST JSON to state/crop-specific ML endpoints

**Result:** `AlertDialog` titled "Yield Prediction"

---

### 4.6 AutomaticDetails

| Property | Value |
|----------|-------|
| **File** | `AutomaticDetails.kt` |
| **Layout** | `activity_automatic_details.xml` |
| **Purpose** | Yield prediction without manual soil lab entry |

**Inputs:** State, lat/long, crop, variety, residue, fertilizers, FYM, dates, irrigation, grain yield (no pH/EC/micronutrient fields)

**Processing:** Same fertilizer conversions; routes to `*_automatic` ML endpoints

**Result:** `AlertDialog` with yield prediction (may include HTML formatting)

---

### 4.7 SoilManagement

| Property | Value |

| **Purpose** | Crop Management Advisory |

**Inputs:** Longitude, latitude, crop (Rice/Wheat), variety (duration), target grain yield

**Processing:** POST to `process_data_rice` or `process_data_wheat`

## 7. Backend APIs

### 7.1 Authentication (PHP)

| Endpoint | Method | Parameters | Used By |
|----------|--------|------------|---------|

### 7.2 Yield Prediction — Manual (ML)

| State Group | Crop | Endpoint |
|-------------|------|----------|
| UP, Bihar | Rice | `/rice_up_bihar` |
| Punjab, Haryana | Rice | `/rice_pb_hr` |
